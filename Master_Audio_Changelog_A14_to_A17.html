Executive Summary

Five Architectural Shifts: Android 14 → 17

Shift 1  ·  Android 14 (Baseline)

The OEM Programmability Revolution

A single release introduced OEM Car Audio Plugin Services, Dynamic Zone Configurations, Audio Mirroring, Passenger Audio Cast, and CAP Engine flags — giving OEMs runtime control of every focus decision for the first time. Schema advanced to v3.

Shift 2  ·  Android 15

System-Enforced Audio Fade

FadeManagerConfiguration and car_audio_fade_configuration.xml closed the compliance gap: CarAudioService can now fade-out non-compliant apps via VolumeShaper without app cooperation. Min/max activation volume added. Schema advanced to v4.

Shift 3  ·  Android 16

CAP Engine Goes AIDL-Native

CAP config migrates from vendor partition XML to live getEngineConfig() AIDL calls. New AudioHalCap* parcelables deliver structured configuration. Breaking: all strategies require STRATEGY_ prefix. Fade/balance getters added; values persist across ignition.

Shift 4  ·  Android 17

Background Audio Hardening

All background audio APIs fail silently without an active FGS. requestAudioFocus() returns AUDIOFOCUS_REQUEST_FAILED. API 37 targets additionally require WIU capability. Every AAOS app playing audio with the screen off must migrate to MediaSessionService or mediaPlayback FGS.

Shift 5  ·  Android 17

USAGE_ASSISTANT Volume Independence

New MODE_ASSISTANT_CONVERSATION and an isolated USAGE_ASSISTANT volume stream break the coupling to STREAM_MUSIC. AAOS OEMs must add a volume group mapping in car_audio_configuration.xml and expose independent controls in Settings UI.

Android 14 → 15

System-Enforced Fade & Activation Volume

AAOS 24Q3  ·  API 34 → 35

1.1 System-Enforced Audio Fade

New Feature audioUseFadeManagerConfiguration = false

When enabled, CarAudioService automatically applies VolumeShaper-based fade-out to apps losing audio focus — without app cooperation.

New Class: FadeManagerConfiguration

public final class FadeManagerConfiguration {
    public static final class Builder {
        public Builder setFadeOutDurationForUsage(int usage, long durationMs);
        public Builder setFadeInDurationForUsage(int usage, long durationMs);
        public Builder setFadeableUsages(List<Integer> usages);
        public Builder setUnfadeableContentTypes(List<Integer> contentTypes);
        public Builder setUnfadeableAudioAttributes(List<AudioAttributes> attrs);
        public FadeManagerConfiguration build();
    }
}

New Class: CarAudioFadeConfiguration

Runtime analog for OEM focus service. Used via OemCarAudioFocusResult.Builder#setAudioAttributesToCarAudioFadeConfigurationMap() to return per-attribute fade configs alongside each focus decision.

New XML: car_audio_fade_configuration.xml

<carAudioFadeConfiguration>
  <fadeConfiguration name="default_fade"
      defaultFadeOutDurationInMillis="500"
      defaultFadeInDurationInMillis="2000">
    <fadeableUsages>
      <usage value="AUDIO_USAGE_MEDIA"/>
    </fadeableUsages>
    <unfadeableContentTypes>
      <contentType value="AUDIO_CONTENT_TYPE_SPEECH"/>
    </unfadeableContentTypes>
    <fadeOutConfigurations>
      <fadeConfiguration usage="AUDIO_USAGE_MEDIA" durationInMillis="300"/>
    </fadeOutConfigurations>
  </fadeConfiguration>
</carAudioFadeConfiguration>

<!-- New in version 4: applyFadeConfigs block inside zoneConfig -->

Users can designate a connected BT headset as primary Audio Output Device in Settings > Sound & Vibration > Audio output. Single media stream constraint applies.

Android 15 → 16

CAP AIDL Migration & Fade/Balance Getters

AAOS 25Q2 + 25Q4  ·  API 35 → 36

2.1 CAP Engine — AIDL Migration

Major Architecture Change

CAP configuration migrates from static vendor partition XML to live AIDL API calls. New devices with Android 16 vendor HAL must expose CAP config via getEngineConfig().

New AIDL Parcelables (android.hardware.audio.core)

  • AudioHalCapConfiguration — top-level config container
  • AudioHalCapCriterionV2 — criterion definitions (e.g., available output devices)
  • AudioHalCapDomain — parameter domain with routing rules
  • AudioHalCapParameter — individual configurable parameter (path + value)
  • AudioHalCapRule — routing and volume decision rules
  • AudioHalEngineConfig.CapSpecificConfig — integration point

Breaking Change: STRATEGY_ Prefix Required

Breaking for OEM CAP Migration

All product strategy names now require the STRATEGY_ prefix in parameter paths.

2.2 AAudio OEM-Defined Audio Attribute Tags

AAudio streams now support OEM-defined tags. Tags integrate with <oemContext> in car_audio_configuration.xml v3+ and must match a CAP strategy when CAP is active.

2.3 Fade and Balance Getter APIs (AAOS 25Q4)

@SystemApi
float getFadeTowardFront();    // [-1.0 rear ... +1.0 front]

@SystemApi
float getBalanceTowardRight(); // [-1.0 left ... +1.0 right]

Values persist per user across ignition cycles. Enables Settings UI to display current state without re-querying HAL.

2.4 HD Radio EAS API (AAOS 25Q2)

Structured API for Emergency Alert System data delivery to radio apps. Supports HD Radio (North America) and DAB EWS (EU).

2.5 AudioControl HAL — Status

Remains at AIDL v3. No v4 confirmed. Architectural changes in Android 16 affect the core Audio HAL, not the automotive AudioControl HAL.

Android 16 → 17

Background Hardening & Assistant Volume

API 36 → 37  ·  Beta May 2026
AAOS-specific CarAudioService API changes and AudioControl HAL v4 have not been confirmed in public documentation as of this document's research date.

3.1 Background Audio Hardening

Critical — All Apps on Android 17

All background audio interactions require a visible Activity or active FGS. APIs fail silently when requirements are not met.

TierScopeRequirement
Tier 1All apps on Android 17Visible Activity OR FGS (not SHORT_SERVICE)
Tier 2Apps targeting API 37FGS with while-in-use capability (e.g., mediaPlayback)

Affected APIs

APIFailure
AudioTrack.write(), AAudioStream_write(), OpenSL ES, ExoPlayerSilent stop
AudioManager.requestAudioFocus()AUDIOFOCUS_REQUEST_FAILED
setStreamVolume(), adjustVolume(), setStreamMute()Silent failure

AAOS Patterns Affected

PatternImpact
Background music with display offNeeds mediaPlayback FGS
Navigation audio with nav app backgroundedNeeds navigation FGS
Boot-triggered audio via BOOT_COMPLETEMust start FGS before audio
VoIP from background processNeeds phoneCall FGS
Alarm/reminder audioSCHEDULE_EXACT_ALARM exempt for USAGE_ALARM

Debug Tools

adb shell cmd audio set-enable-hardening enable   # Enforce
adb shell cmd audio set-enable-hardening throw    # Enforce + throw exceptions
adb shell cmd audio set-enable-hardening disable  # Disable
adb logcat | grep AudioHardening                  # Monitor violations

3.2 Dedicated Assistant Volume Stream

New

AudioManager.MODE_ASSISTANT_CONVERSATION + isolated USAGE_ASSISTANT volume stream. Media and Assistant can now be muted/adjusted independently.

audioManager.setMode(AudioManager.MODE_ASSISTANT_CONVERSATION); // Start assistant
audioManager.setMode(AudioManager.MODE_NORMAL);                 // End assistant

AAOS action required: Map USAGE_ASSISTANT to a volume group in car_audio_configuration.xml and expose independent volume control in Settings.

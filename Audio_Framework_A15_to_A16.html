CarAudioService Updates Java Service Layer

AAudio OEM-Defined Audio Attribute Tags

The AAudio native audio library now supports OEM-defined audio attribute tags on audio streams. These tags are consumed by CarAudioService and the CAP engine for routing decisions and volume management without requiring app code changes.

Tags integrate with <oemContext> elements in car_audio_configuration.xml v3+:

<oemContexts>
  <oemContext name="oem_music_high_priority">
    <audioAttributes>
      <usage value="AUDIO_USAGE_MEDIA"/>
    </audioAttributes>
  </oemContext>
</oemContexts>
  • When CAP is active (useCoreAudioRouting=true), each OEM-defined context must match a CAP engine product strategy
  • Enables per-stream audio routing customization entirely within the OEM audio policy layer

Fade and Balance Getter APIs (AAOS 25Q4)

New APIs — completing read/write parity for fade and balance:

@SystemApi
float getFadeTowardFront();     // Returns current fade value [-1.0, +1.0]

@SystemApi
float getBalanceTowardRight();  // Returns current balance value [-1.0, +1.0]
  • Corresponding write methods (setFadeTowardFront, setBalanceTowardRight) have existed since Android 9
  • Prior to Android 16 there was no way to query current fade/balance values
  • Values persist per user across ignition cycles, enabling the Audio Settings UI to show correct state after reboot

Alternative App Audio Controls (AAOS 25Q4)

  • Users can independently control volume of communication apps (phone calls, VoIP) while driving
  • New system audio routing path separates communication audio from media center audio
  • Addresses the gap where VoIP apps had no user-accessible volume control when the media stack owned the volume buttons

car_audio_configuration.xml — Unchanged at Version 4

No new schema version in Android 16. The schema remains at version 4 (introduced in Android 15). No new XML elements confirmed for this transition.

AudioControlService Updates C++ Proxy Layer
The automotive-specific AudioControlService C++ proxy remains at AIDL v3 with no interface changes in Android 16.

The major architectural changes in Android 16 target the core Audio HAL (android.hardware.audio.core), which handles policy engine configuration. The IAudioControl interface — responsible for fade, balance, focus signals, ducking, and muting in automotive contexts — is not modified.

AudioControlHAL Updates HAL Layer

No New AudioControl HAL Version

AudioControl HAL remains at AIDL v3 in publicly documented AOSP for Android 16. No AIDL v4 IAudioControl has been confirmed.

Major Change: CAP Engine AIDL Migration (android.hardware.audio.core)

While this change is in android.hardware.audio.core rather than android.hardware.automotive.audiocontrol, it directly governs how the audio policy engine — which CarAudioService depends on for routing and volume — is configured.

CAP configuration is now delivered via a live AIDL call (getEngineConfig()) rather than static vendor partition XML parsing.

New AIDL parcelables (namespace: android.hardware.audio.core):

parcelable AudioHalCapConfiguration { /* Aggregates criteria, domains, parameters */ }

parcelable AudioHalCapCriterionV2 {
    String name;  // e.g., "available output devices", "telephony mode"
}

parcelable AudioHalCapDomain {
    String name;
    AudioHalCapParameter[] parameters;
    AudioHalCapRule[] rules;
}

parcelable AudioHalCapParameter {
    String path;   // e.g., "/Policy/policy/product_strategies/STRATEGY_MEDIA/device_address"
    String value;
}

parcelable AudioHalCapRule { /* Condition criteria and parameter assignments */ }

// Integration point in AudioHalEngineConfig:
parcelable AudioHalEngineConfig {
    @nullable CapSpecificConfig capSpecificConfig;  // NEW in Android 16
}

parcelable CapSpecificConfig {
    AudioHalCapConfiguration configuration;
    AudioHalCapCriterionV2[] criteria;
    AudioHalCapDomain[] domains;
}

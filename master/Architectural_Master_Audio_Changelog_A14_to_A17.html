Executive Summary: Five Macro Architectural Shifts (A14 → A17)
Android 14
Shift 1 — The OEM Programmability Revolution

A single release introduced OEM Car Audio Plugin Services (intercepting every focus decision via OemCarAudioFocusService), Dynamic Audio Zone Configurations (runtime switching via switchAudioZoneToConfig()), Audio Mirroring (enableMirrorForAudioZones()), Passenger Audio Cast (requestMediaAudioOnPrimaryZone()), and CAP Engine flags (useCoreAudioVolume, useCoreAudioRouting). car_audio_configuration.xml advanced to version 3.

Android 15
Shift 2 — System-Enforced Audio Fade

FadeManagerConfiguration, car_audio_fade_configuration.xml, and audioUseFadeManagerConfiguration gave CarAudioService the ability to apply VolumeShaper-based fade-out to non-compliant apps without their cooperation. audioUseMinMaxActivationVolume added first-ever min/max volume enforcement at audio activation time. Schema advanced to version 4.

Android 16
Shift 3 — CAP Engine Goes AIDL-Native (Final HIDL Retirement)

The CAP engine's config mechanism migrated from static vendor partition XML to live AIDL calls via AudioHalCapConfiguration, AudioHalCapCriterionV2, AudioHalCapDomain, AudioHalCapParameter, AudioHalCapRule, and AudioHalEngineConfig.CapSpecificConfig. Breaking change: all product strategy names now require the STRATEGY_ prefix. This marks the final phase of HIDL retirement for automotive audio on new devices.

Android 17
Shift 4 — Background Audio Hardening

System-enforced Foreground Service requirements for all background audio interactions. AudioTrack.write(), requestAudioFocus(), volume APIs fail silently without a visible Activity or non-SHORT_SERVICE FGS. Apps targeting API 37 additionally require while-in-use FGS. Impacts every AAOS app that plays audio with the screen off, starts audio on BOOT_COMPLETE, or manages background VoIP/navigation audio.

Android 17
Shift 5 — USAGE_ASSISTANT Volume Independence

AudioManager.MODE_ASSISTANT_CONVERSATION and the isolation of USAGE_ASSISTANT into its own volume stream break the long-standing coupling between assistant audio and media volume. AAOS OEMs must map the new stream to a volume group in car_audio_configuration.xml and expose independent volume controls in Audio Settings UI.

CarAudioService Updates Java Service Layer
Android 15 · AAOS 24Q3

System-Enforced Audio Fade

  • Flag: audioUseFadeManagerConfiguration (default: false, OEM RRO)
  • New class: FadeManagerConfiguration (android.car.media) — Builder API: setFadeOutDurationForUsage(), setFadeInDurationForUsage(), setFadeableUsages(), setUnfadeableContentTypes(), setUnfadeableAudioAttributes(). Default fade-out: 500 ms; fade-in: 2000 ms.
  • New class: CarAudioFadeConfiguration (android.car.media) — runtime analog for OEM focus plugin integration
  • New XML: car_audio_fade_configuration.xml on vendor overlay partition
  • car_audio_configuration.xml → Version 4 with <applyFadeConfigs> / <fadeConfig> elements (exactly one must have isDefault="true" per zone config)

Minimum and Maximum Activation Volume

  • Flag: audioUseMinMaxActivationVolume (default: false, OEM RRO)
  • New XML element: <activationVolumeConfig> with invocationType: onBoot | onSourceChanged | onPlaybackChanged
  • Monitoring via AudioPlaybackCallback, call-state changes, HAL IFocusListener#requestAudioFocus()

OEM Focus Plugin — Per-Attribute Fade Configuration

  • New builder method: OemCarAudioFocusResult.Builder#setAudioAttributesToCarAudioFadeConfigurationMap(Map<AudioAttributes, CarAudioFadeConfiguration>)
  • Android 15 adds ability for OEM focus service to specify per-attribute fade treatment alongside focus decisions

Bluetooth Headset as Primary Audio Output Device

  • User-selectable via Settings > Sound & Vibration > Audio output
  • Routes via AUDIO_DEVICE_OUT_BUS infrastructure; single active BT stream constraint
Android 16 · AAOS 25Q2 + 25Q4

AAudio OEM-Defined Audio Attribute Tags

  • OEM tags on AAudio streams consumed by CarAudioService for routing and volume decisions
  • Integrates with <oemContext> in car_audio_configuration.xml v3+
  • When CAP active (useCoreAudioRouting=true): OEM context must match a CAP engine product strategy

Fade and Balance Getter APIs (AAOS 25Q4)

  • New @SystemApi: getFadeTowardFront() — returns current fade value [-1.0, +1.0]
  • New @SystemApi: getBalanceTowardRight() — returns current balance value [-1.0, +1.0]
  • Values persist per user across ignition cycles
  • car_audio_configuration.xml unchanged at Version 4

Alternative App Audio Controls (AAOS 25Q4)

  • Independent volume control for communication apps (phone calls, VoIP) alongside media
  • Separate audio routing path separates communication audio from media center audio
Android 17 · API Level 37 (Beta)

Background Audio Hardening — Critical

Applies to all apps on Android 17 devices regardless of target SDK.

AAOS patterns affected: background music (display off), boot-triggered audio, backgrounded nav audio, background VoIP, HAL focus requests.

Dedicated Assistant Volume Stream

  • New constant: AudioManager.MODE_ASSISTANT_CONVERSATION
  • USAGE_ASSISTANT isolated into its own volume stream — independent of STREAM_MUSIC
  • AAOS OEM action: update car_audio_configuration.xml volume group + Audio Settings UI

No New AAOS-Specific APIs Confirmed

CarAudioService architecture, car_audio_configuration.xml (stays v4), audio zone APIs, volume group APIs, OEM plugin interfaces — no changes confirmed for Android 17.

AudioControlService Updates C++ Proxy Layer
Android 15 · 16 · 17 — No Changes
The AudioControlService C++ proxy layer had no interface changes in any of the Android 15, 16, or 17 releases. It remains on AIDL v3 throughout the entire A14–A17 period.

Each architectural change across these releases operates at a different layer:

  • Fade/volume enforcement (A15): Java CarAudioService layer using VolumeShaper
  • CAP engine config migration (A16): android.hardware.audio.core (not IAudioControl)
  • Background audio hardening (A17): audioserver platform enforcement layer

The IAudioControl AIDL v3 interface is identical in Android 14, 15, 16, and 17.

Android 16 — CAP Engine AIDL Migration (android.hardware.audio.core)

The most significant HAL-layer change in the A14–A17 span. While in android.hardware.audio.core (not IAudioControl directly), it governs how the audio policy engine — which CarAudioService depends on — is configured.

New AIDL parcelables (namespace: android.hardware.audio.core):

parcelable AudioHalCapConfiguration { /* Top-level CAP config */ }
parcelable AudioHalCapCriterionV2 { String name; /* criterion type + values */ }
parcelable AudioHalCapDomain { String name; AudioHalCapParameter[] parameters; AudioHalCapRule[] rules; }
parcelable AudioHalCapParameter { String path; String value; }
parcelable AudioHalCapRule { /* routing/volume rules evaluated against criteria */ }

// Integration point in AudioHalEngineConfig
parcelable AudioHalEngineConfig {
    @nullable CapSpecificConfig capSpecificConfig;  // NEW in Android 16
}
parcelable CapSpecificConfig {
    AudioHalCapConfiguration configuration;
    AudioHalCapCriterionV2[] criteria;
    AudioHalCapDomain[] domains;
}
⚠️ Breaking Change: STRATEGY_ Prefix Required All product strategy names require the STRATEGY_ prefix in Android 16+. Example: media → STRATEGY_MEDIA, phone → STRATEGY_PHONE. OEM extension slots vx_1000–vx_1039 are unchanged.

HIDL Final Retirement

HIDL-based AudioControl HAL versions (1.0, 2.0) have been deprecated since Android 12L. The Android 16 CAP AIDL migration marks the point where new devices with fully updated vendor HALs have no remaining HIDL dependency in the automotive audio stack. Devices upgrading from Android 14/15 vendor HALs retain a supported XML-fallback path via EngineConfigXmlConverter.h.

CarAudioService Updates Java Service Layer

Background Audio Hardening (Critical — All Apps)

This is the most impactful audio framework change in Android 17 for AAOS apps.
This change applies to all apps running on Android 17 devices regardless of target SDK version.

The platform audio stack enforces that any app interacting with audio APIs from the background must hold a visible Activity or an active FGS.

TierScopeRequirement
Tier 1All apps on Android 17 devicesVisible Activity OR FGS (not SHORT_SERVICE)
Tier 2Apps targeting API Level 37 onlyFGS must have while-in-use (WIU) capability (e.g., mediaPlayback)

Exception: WIU waived when app holds SCHEDULE_EXACT_ALARM AND only uses USAGE_ALARM streams.

Required manifest declaration (apps targeting API 37):

<service
    android:name=".AudioPlaybackService"
    android:foregroundServiceType="mediaPlayback"
    android:exported="false"/>

Recommended migration — Option A (preferred): Adopt MediaSessionService (media3):

public class CarMediaService extends MediaSessionService {
    @Override
    public MediaSession onGetSession(MediaSession.ControllerInfo controllerInfo) {
        return mediaSession;
    }
    // MediaSessionService manages FGS lifecycle automatically
}

Dedicated Assistant Volume Stream

New constant: AudioManager.MODE_ASSISTANT_CONVERSATION

  • USAGE_ASSISTANT audio is now isolated into its own volume stream, separate from STREAM_MUSIC
  • Users can independently mute media while keeping Assistant responses audible, and vice versa
  • Volume panel in Quick Settings exposes the Assistant stream as a separate slider
// Signal active voice assistant conversation
audioManager.setMode(AudioManager.MODE_ASSISTANT_CONVERSATION);

// When conversation ends
audioManager.setMode(AudioManager.MODE_NORMAL);
AspectAndroid 16Android 17
USAGE_ASSISTANT volumeShared with STREAM_MUSICIsolated independent volume stream
Media mute affects assistantYesNo — streams are independent
Volume panelSingle media sliderSeparate assistant slider

AAOS OEM action required: Map the new stream to a volume group in car_audio_configuration.xml:

<group name="assistant_group">
  <context>
    <usage value="AUDIO_USAGE_ASSISTANT"/>
  </context>
</group>

AudioControlService Updates C++ Proxy Layer
No changes to the AudioControlService C++ proxy layer in Android 17. AIDL v3 IAudioControl remains current.

Background audio hardening enforcement occurs at the platform audio framework level (Java AudioManager and AudioTrack enforcement in audioserver). No AIDL changes to the automotive IAudioControl proxy are required.

AudioControlHAL Updates HAL Layer
AudioControl HAL remains at AIDL v3 — no AIDL v4 confirmed in public AOSP documentation for Android 17.

Other Platform Audio Changes with AAOS Relevance

BLE Hearing Aid Device Type: New constant AudioDeviceInfo.TYPE_BLE_HEARING_AID distinguishes BLE hearing aids from TYPE_BLE_HEADSET. OEMs supporting accessible audio should update device-picker UIs.

xHE-AAC Software Encoder: New system-provided encoder c2.android.xheaac.encoder with mandatory loudness metadata. Relevant for in-vehicle streaming and voice call recording pipelines.

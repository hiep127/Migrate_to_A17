1 · Low risk

MaxVolumeStartup

A whole new Nissan-only file, absent from AOSP. Provides a per-AudioAttributes-usage default-volume lookup backed by SystemProperties, replacing AOSP's flat "1/3 of range" default for core-audio volume groups. persist.vendor.max_vol_startup is a factory first-boot ceiling, consulted only when there's no valid persisted user value — not a per-ignition re-clamp. 

final class CoreAudioVolumeGroupHelper {
    static int getDefaultVolumeForAttributes(AudioAttributes attrs, int maxGain, int minGain,
            CoreAudioVolumeGroup volumeGroup) {
        // switch on attrs.getUsage() -> SystemProperties key, validated against
        // volumeGroup.isValidGainIndexLocked(...), falls through to (maxGain-minGain)/3+minGain

        // Media/Game/Unknown:
        int maxVolumeStartUp = SystemProperties.getInt("persist.vendor.max_vol_startup", -1);
        int defaultVolume    = SystemProperties.getInt("ro.config.media_vol_default", -1);
        return (defaultVolume != -1 && maxVolumeStartUp != -1)
                ? Math.min(defaultVolume, maxVolumeStartUp)
                : (maxVolumeStartUp != -1 ? maxVolumeStartUp : defaultVolume);
    }
}

Change: add the file as-is; wire the call into CoreAudioVolumeGroup.java's constructor at the spot the stock fallback formula lives (keep that formula as the tail case). Gated behind audioUseCoreVolume=true.

Verify: fresh data wipe clamps first-boot MEDIA volume to the sysprop value; a later boot with a persisted value does not re-clamp.

ANR fix on playback callback

+mAudioManager.registerAudioPlaybackCallback(mCarAudioPlaybackCallback, mHandler);

6 · Do late

Audio Off mode

Implemented as a MEDIA-volume-group-mute proxy — no independent mode flag or Settings observer. Whatever mutes the primary zone's MEDIA group (an app calling the standard CarAudioManager.setVolumeGroupMute(), an HMI control) flows through the ordinary mute path; handleMuteChanged()'s media-group branch is the entire hook. 

// CarAudioService.handleMuteChanged()
private void handleMuteChanged(int zoneId, int groupId, int flags) {
    if (!mUseCarVolumeGroupMuting) { return; }
    if (groupId == getVolumeGroupIdForUsage(PRIMARY_AUDIO_ZONE, USAGE_MEDIA)) {
        CarVolumeGroup group_media = getCarVolumeGroupLocked(zoneId, groupId);
        mFocusHandler.applyUserMuteAudioFocusPolicy(zoneId, group_media.isMuted());
    }
    callbackGroupMuteChanged(zoneId, groupId, flags);
    callbackMasterMuteChange(zoneId, flags);   // <- master-mute callback conflation
    mCarVolumeGroupMuting.carMuteChanged();
}

// CarAudioFocus.java — a single per-zone boolean, not per-FocusEntry state
private boolean mUserMuted = false;

void applyUserMuteAudioFocusPolicy(boolean userMuted) {
    synchronized (mLock) {
        mUserMuted = userMuted;
        if (userMuted) { return; }
        removeBlockerAndRestoreUnblockedFocusLosersLocked(null);
    }
}

// restoration guard: entertainment focus losers stay parked while muted
if (entry.isUnblocked() && !(mUserMuted && isEntertainmentSource(entry))) { /* restore */ }

Change: CarAudioService.java (handleMuteChanged), CarZonesAudioFocus.java (new applyUserMuteAudioFocusPolicy fan-out), CarAudioFocus.java (mUserMuted, isEntertainmentSource(), the guard above). No change to FocusEntry.java.

A17's fade-manager focus-loss dispatch is currently inert (audioUseFadeManagerConfiguration=false); if it's ever enabled later, re-test this guard composes with it correctly.

Verify: muting MEDIA blocks entertainment auto-resume; unmuting restores it; onMasterMuteChanged fires on MEDIA-group mute specifically; persists across reboot per item 2's sysprop.

8 · Low-Med risk

Suspend-exit volume limiting

8a. The HAL's SUSPEND_EXIT_VOL_LIMITATION reason targets one bus (media) — scope it so non-media groups sharing that bus don't inherit the limit, and clamp stale pre-suspend volume down to the HAL-reported ceiling:

if (shouldLimit && CarAudioGainMonitor.isSuspendReason(halReasons) && !hasMediaUsage) {
    shouldLimit = false;
}
if (CarAudioGainMonitor.isSuspendReason(halReasons) && hasMediaUsage
        && (mCurrentGainIndex > halIndex)) {
    mCurrentGainIndex = halIndex;
}

8b. A broader safety net — reset every primary-zone group's limit state on suspend/hibernation exit:

private void handlePowerState(int powerState) {
    CarVolumeGroup[] groups = getCarAudioZoneLocked(PRIMARY_AUDIO_ZONE).getCurrentVolumeGroups();
    switch (powerState) {
        case CarPowerManager.STATE_SUSPEND_EXIT:
        case CarPowerManager.STATE_HIBERNATION_EXIT:
            for (int i = 0; i < groups.length; i++) { groups[i].resetLimitLocked(); }
            break;
        default: break;
    }
}

Change: CarVolumeGroup.java (8a, same method as item 7 — implement together), CarAudioService.java (8b — new ICarPowerStateListener, registered in init() alongside item 3). resetLimitLocked() itself already exists in a17full; only the trigger wiring is missing. a17full's existing CarAudioPowerListener.java is unrelated (power *policy*, not power *state*).

Verify: suspend/wake doesn't leave media stuck limited or too loud; non-media groups on the shared bus unaffected; reset fires only on the two named states.
